Agent 工程的五次范式演进

Prompt Engineering → Context Engineering → Harness Engineering → Loop Engineering → Graph Engineering
演进主线:工程化的优化对象不断放大 —— 从 一段话 → 整个上下文 → 运行环境 → 迭代循环 → 系统拓扑
1

提示词工程

Prompt Engineering
约 2022–2023 · ChatGPT 时代
优化对象喂给模型的一段提示文本
"把话说对,模型就能做对。"
  • 零样本 / 少样本提示(Few-shot)
  • 思维链 CoT、角色设定、指令模板
  • 单轮或少量轮次交互,无外部工具
  • 靠人工试错调措辞,带"玄学"色彩
  • 效果脆弱:换模型、换措辞即失效
  • 难以复用、难以系统化沉淀
Few-shot CoT Role Play Prompt 模板

上下文工程

Context Engineering
约 2023–2024 · RAG 与长上下文时代
优化对象整个上下文窗口的内容组装
"在对的时间,把对的信息放进上下文。"
  • RAG 检索增强,动态注入外部知识
  • 记忆管理:短期对话 + 长期记忆
  • 上下文压缩、裁剪与优先级排序
  • 工具返回结果的结构化注入
  • 关注信息质量,而非措辞技巧
  • 上下文成为稀缺资源,需要精打细算
RAG Memory Compaction Embedding 检索
➜
3

脚手架工程

Harness Engineering
约 2024–2025 · Coding Agent 时代
优化对象模型之外的运行环境与工具链
"模型不变,更好的 harness 释放更强能力。"
  • 工具接口设计:读写文件、执行 shell
  • 沙箱环境,安全地执行与试错
  • 自动验证反馈:跑测试、lint、编译
  • 子代理分工,隔离上下文、并行探索
  • 权限与人机协作机制内建于环境
  • 同一模型换 harness,表现天差地别

循环工程

Loop Engineering
Agentic 工作流时代
优化对象Agent 的迭代控制循环本身
"智能来自循环的质量:感知-规划-行动-反思。"
  • ReAct / Plan-Act-Observe 循环结构
  • 停止条件、步数与 token 预算控制
  • 错误恢复:重试、回退、换策略
  • 自我批评与反思(Self-Reflection)
  • 长任务的进度追踪与状态持久化
  • 循环节奏决定 agent 的可靠性与成本
ReAct Reflection Budget 控制 Checkpoint
➜
5

图工程

Graph Engineering
多智能体系统时代
优化对象多节点、多智能体的控制流拓扑
"把 agent 系统建模为状态图,而非一条单链循环。"
  • 状态图建模:节点 = 能力,边 = 流转
  • 条件路由:按状态动态选择下一节点
  • 并行分支与汇聚,扇出/扇入控制
  • 多智能体编排与角色分工协作
  • 人在回环节点(Human-in-the-loop)
  • 工作流可持久化、可回放、可观测

演进规律:优化对象不断升维,工程确定性不断增强

一段提示文本 → 整个上下文窗口 → 模型运行环境 → 迭代控制循环 → 系统拓扑结构

从"调一句话"到"设计一个系统":提示词工程依赖玄学试错,上下文工程开始管理信息流,脚手架工程把环境本身变成可设计的对象, 循环工程让 agent 具备自我校正的迭代能力,图工程则把多个 agent 协作编排为显式、可控、可观测的状态机。 五个阶段并非相互替代,而是层层叠加 —— 一个成熟的 Agent 系统同时需要这五个层面的工程能力。
