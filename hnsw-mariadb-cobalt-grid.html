五个入口函数

  • `VEC_DISTANCE_EUCLIDEAN(a,b)`：逐维平方差求和再开方。
  • `VEC_DISTANCE_COSINE(a,b)`：`1 - dot/sqrt(abs1*abs2)`。

  • `VEC_TOTEXT(vector)`：内部二进制转文本数组。

VECTOR KEY 绑定 MHNSW

sql_table.cc / vector_mhnsw.cc

DDL

`Key::VECTOR` 进入 `mysql_prepare_create_table()`。

Algorithm

默认设置为 `HA_KEY_ALG_VECTOR`。

Plugin

绑定 `mhnsw_plugin` 和 `mhnsw_index_options`。

Options

`m` 控制邻居数量，`distance` 控制度量。

HL Index

创建隐藏辅助图表，保存 HNSW 结构。

M

默认 `mhnsw_default_m = 6`，越大召回越高，但 SELECT/INSERT 更慢、索引和内存更大。

ef

`mhnsw_ef_search` 控制查询候选下限，越大通常越准但越慢。

cache

`mhnsw_max_cache_size` 是单个 MHNSW vector index cache 的上限。

004

图节点：FVectorNode

one auxiliary row / one graph node

身份

`gref` 指向辅助图表记录，`tref` 指向主表记录。搜索命中图节点后，最终靠 `tref` 回主表随机读。

向量

`vec` 不是原始 float 数组，而是预处理后的 `FVector`，包含量化维度和距离计算所需派生值。

邻居

`neighbors` 按层保存邻居列表。第 0 层最多 `2*M`，其它层最多 `M`。

class FVectorNode {
  const FVector *vec;
  Neighborhood *neighbors;
  uint8_t max_layer;
  bool stored:1, deleted:1;
  float distance_to(const FVector *other) const;
  int load(TABLE *graph);
  int save(TABLE *graph);
};

005

向量内部表示

float array -> scale + int16 dims

量化路径

`FVector::create()` 先找最大绝对值，再计算 `scale`，把每维 float 映射到 `int16_t dims[]`。随后执行 `postprocess()` 生成 `abs2/subabs2`，cosine 距离还会做额外归一化。

距离近似

距离计算通过 dot product 还原近似平方距离：`abs2 + other.abs2 - scale * other.scale * dot(dims, other.dims)`。这减少长期缓存里的向量体积，也让搜索里的距离比较更便宜。

scan max

找到最大绝对值。

scale

计算 float 到 int16 的比例。

dims

逐维 round 到 int16。

postprocess

缓存 abs2 / subabs2。

distance

用 dot product 快速比较。

插入建图流程

mhnsw_insert()

first row

图为空时，新节点直接作为 `ctx->start`。

random layer

按指数分布生成层数，最高不超过当前最高层 + 1。

upper search

高于目标层时，每层只保留 1 个最近入口。

select neighbors

目标层到第 0 层，搜索候选并选择邻居。

back links

保存新节点后更新二阶邻居反向连接。

查询如何走 HNSW

ORDER BY VEC_DISTANCE(...) LIMIT N

优化器匹配条件

  • `ORDER BY` 只有向量距离函数。
  • 排序方向是升序。
  • 参数中一个是字段，另一个是常量。
  • 函数距离类型与 vector index 的 `distance` 一致。

执行入口

匹配后，`sql_select.cc` 把 read_record 函数切到 `join_hlindex_read_next`，然后调用 `hlindex_read_first()`，最终进入 `mhnsw_read_first()`。

highest

从 `ctx->start` 最高层开始。

layer down

高层每层搜索 1 个入口。

layer 0

第 0 层搜索 LIMIT 个候选。

context

结果进入 `Search_context`。

row fetch

`mhnsw_read_next()` 用 `tref` 回主表。

search_layer() 的两个队列

candidate expansion / best set

candidates

待扩展节点队列。每次弹出当前候选，扫描它在当前 layer 的邻居，并把没有访问过的邻居按距离加入搜索过程。

best

当前最近结果集合。`best` 已满且当前候选距离比最差 best 更远时，可以提前停止，因为后续候选不再可能改善结果。

ef = construction ? max(ef_construction, result_size)
                  : max(mhnsw_ef_search, result_size)

skip_deleted = !construction && layer == 0

while candidates not empty:
  cur = candidates.pop()
  if cur.distance > furthest_best && best.is_full():
    break
  scan cur.node->neighbors[layer]
  push better nodes into candidates and best

DML and transaction cost

事务应用的核心影响，不是距离计算本身

vector index 把一次主表 DML 扩展成「主表变更 + 隐藏辅助图表变更 + 内存图缓存维护」。写入放大、锁竞争和缓存失效才是 OLTP 风险点。

012

DML 写路径

handler hooks / sql_base.cc
insert

同步维护图

`hlindexes_on_insert()` 在主表插入后调用 `mhnsw_insert()`，新节点会触发图搜索、新节点保存和邻居更新。

update

逻辑删除 + 插入

`hlindexes_on_update()` 先 `mhnsw_invalidate()` 旧节点，再 `mhnsw_insert()` 新节点，成本接近 delete + insert。

delete

tombstone

删除不是物理移除节点，而是辅助表 `tref = NULL`，内存节点 `deleted = true`。第 0 层查询跳过，高层仍可导航。

locks

邻居热点

多个事务插入相近向量时，可能争抢相同邻居节点的隐藏图表行，风险表现为 lock wait、deadlock 和 commit P99 上升。

013

事务本地缓存与 COMMIT 抖动

MHNSW_Trx / commit_lock / ctx_version

MHNSW_Trx

事务第一次需要 HNSW 上下文时创建，挂在 `thd->ha_data[]`，分配在 `thd->transaction->mem_root`。

长事务

批量写 vector 表时，节点、量化向量、邻居数组和搜索加载节点可能在事务期间保留，推高内存峰值。

提交

`do_commit()` 拿共享图 `commit_lock` 写锁，递增 `version`，失效共享缓存节点或 reset 整个缓存。

if (ctx->version != result->ctx_version) {
  // shared ctx was modified
  // switch to MHNSW_Trx and reload result nodes
}

读写混合场景中，查询可能在结果读取期间遇到版本变化，产生额外重加载成本。
